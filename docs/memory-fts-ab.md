# FTS 检索配对与延迟实验（第 6/6 步）

2026-10-11：**评测器、离线两分支与真实四分支混合对照及缓存复跑全部完成（6/6）**。
不切换默认，不改私有 `.env`，不操作真实聊天库；不运行 Kimi 或核对实际账单。
报告见 [离线实测](../evals/baselines/memory-fts-ab-v1-2026-10-11.md)与
[真实四分支和资源记录](../evals/baselines/memory-fts-hybrid-ab-v1-2026-10-11.md)。

## 固定什么

- 复用原用户审核锁定的 24 条合成题，开发/个人各半；现在是已见回归集，不是新盲测。
- 从 gold 原文通过手动记忆 API 注入事实。没有 Agent 提炼、状态分类或回复评测。
- 每题各分支使用同一 SQLite 库、全部房间相同语料、相同记忆 ID/时间/原文。
  查询前后规范记忆（含非活跃历史）与来源消息的哈希不变。
- limit=3、候选上限=200、RRF=60、向量阈值=0.65；不按这批题调参。
- 旧分支的 24 条有序来源必须仍匹配第 1 步冻结文件，题库/审核锁/约定漂移即失败。

[SQLite 官方 BM25 说明](https://www.sqlite.org/fts5.html#the_bm25_function)中，
文档平均长度与 IDF 使用整个 FTS 表的语料统计。因此实验固定同一语料库；
同房间返回过滤不代表 BM25 评分统计实现了租户隔离。每题独立临时库，
也不等于所有线上房间的大语料排名效果。

## 三种运行模式

```bash
# 默认离线，2 分支，不读取 Settings/.env、不联网
.venv/bin/python -m evals.run_memory_fts_ab

# 显式付费采集，4 分支，无 Agent，最多 50 次 embedding 请求
.venv/bin/python -m evals.run_memory_fts_ab --embed --max-calls 50

# 用一次已完成采集的缓存复验 4 分支，不读私有配置、不联网
.venv/bin/python -m evals.run_memory_fts_ab --cache /绝对路径/embedding-cache.json
```

四分支为 `legacy`、`bm25`、`legacy_hybrid`、`bm25_hybrid`。
云采集使用现有 OpenAI 兼容接口和本机 embedding 配置；阈值固定 0.65，
不隐式使用配置中的其他阈值。沿用生产逐条索引、敏感文本保护和查询清洗，
同一文本哈希只采集一次。每题采集完冻结缓存，两个混合分支共享相同向量。
所有计时重复均不访问云端，输出独立的实际 API 调用/文本数、provider 延迟与
provider 报告的 token 数（缺少 usage 时不推算）。不计算或声称实际账单金额。

完整缓存保存输入文本 SHA-256、向量、模型/修订号、模型指纹、题库哈希与校验和，
不保存密钥、请求头或私有 endpoint。缓存用于本地可信实验复跑，**不是签名证据或
安全认证**；人工改内容并重算校验和仍可伪造来源。仅接受已完成采集且校验、数据、
向量维度/有限数值合法的缓存。重放缺失输入严格失败，不自动联网补齐。

## 防止假成绩

生产检索可降级以保持可用，实验却必须严格区分：

- BM25 的 FTS 查询未运行、返回不可用状态、抛出异常/超限或索引非 ready：实验失败。
  成功查询返回空集合是有效结果，不能误判成故障。
- 向量索引或搜索抛错、缓存缺失、达到调用上限：实验失败，不算记忆漏召回。
- 规范事实变化、重复读取有序来源变化或旧冻结结果漂移：实验失败。
- 不完整运行保留已完成逐题文件/缓存和 `complete=false` 清单，不能作为完整成绩。
  当前不实现自动断点续跑；不完整缓存也不允许作为完整四分支重放输入。

单元测试中的假向量只验流程/缓存/预算/错误处理，写在 pytest 临时目录；
不能用来宣称混合检索质量提升。历史 2026-10-10 的 12/12 混合召回是旧关键词分支的
独立实验，其文件未保存向量，不能冒充本轮新 BM25 混合结果。

## 延迟范围与指标

每题先读一次确定输出，默认再预热 3 次，每分支测 20 次。每轮/每题反转执行顺序，
减少固定先后顺序偏差；SQLite 连接、候选读、排序、最终规范复验在计时内，严格实验
状态检查在计时外。诊断包装只在调用内记录 FTS/vector 成败，有少量共同开销。

这测的是单进程、本机、小语料、热文件缓存下的 `retrieve`，不包括建库、初始化、
写入/回填、云请求、Agent 回复。混合分支是 **cached-embedding 本地重放延迟**，
不是线上云 embedding 端到端延迟。API 采集延迟另列，不能与缓存延迟相加当真实回合。
480 次样本包含空候选短路，因此也分列非空候选与空候选分布；无负载测试、置信区间
或 SLA 承诺，不外推 200 候选的性能。

来源级 Recall@3/Precision@3、正样本查询 MRR@3、空 gold 误召回、配对增益/退化与
有序结果变化分别报告。24 题只有 12 个应召回来源，不是 24 个答案的通过率。

清单记录题库/锁/旧冻结 SHA、相关代码 SHA、Python/SQLite/平台/分词版本、参数、
缓存指纹和调用计数；逐题记录规范快照哈希、原始计时样本、来源及评分。
输出到忽略目录 `evals/results/memory-fts-ab-v1/<run-id>/`，不覆盖旧实验。

## 当前决策

离线结果没有证明新 BM25 的质量或速度收益：保持默认 `legacy`，保留显式 `bm25`
配置和恢复能力。经用户确认采集的真实四分支中，两关键词均 10/12，两混合均 12/12，
无误召回；BM25 没有额外增益，不切默认。成功采集 34 请求、430 个报告 token、
0 Agent；加上先前沙箱失败的 1 次尝试共 35 次，低于已确认上限 50。缓存无网复跑
24×4 有序来源一致、请求 0 次。外部向量数据库/ANN 仍是独立后续阶段，未在本轮实现。
