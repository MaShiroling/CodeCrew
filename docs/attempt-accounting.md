# 第 6 项第 4 子步骤 A：失败与取消成本记账

本增量修复“只有正常返回的回合才计入预算”的漏洞。仅离线 Fake 验证，
没有开放 HTTP 继续执行，也没有实现完整人工故障恢复。

## 生命周期

1. `WorkflowDirectiveExecutor` 将可信记账回调传给 `AgentTurnRunner`。
2. 获得 Registry 租用、检查选定消息后，在 `start/resume` **之前**写入一次尝试：
   服务端生成 attempt ID，绑定 task、trace、room、member、角色与适配器名称。
   写入失败则不调用适配器；进程在此后崩溃，预留记录仍占用一次回合。
3. 在 `finally` 更新本地单调时钟测量的耗时；有匹配 session/trace 的结果时，
   保存其已报告 Token，耗时取本地测量与适配器报告的较大值。
4. 解析、Artifact 完整性检查、可信审计、路由及 ACK 在记账之后。
   因此格式/审计拒绝也不能逃避预算。记账不构成 ACK、批准或任务完成证据。

启动失败、Adapter 异常、非零退出、超时和取消均保守占用一次派发尝试。
这表示一次尝试，不代表一定发送了模型请求或产生账单。排队/预检拒绝不计尝试。

沿用 Migration 6 的账本，无数据库迁移。旧 `session_id` 列在新派发中保存
**attempt ID**，不是实际 CLI 会话 ID；原生会话证据仍由原有诊断和 Artifact 保存。
旧 `record_turn` 接口继续支持按实际 session ID 导入完整回合，生产 Executor
不再额外调用它，避免重复计数。

## 幂等与未知值

- 同一 attempt 的身份和开始时间必须一致；已知 Token 冲突则拒绝更新。
- 重放不能擦除已知 Token，也不能降低累计耗时；未知值可以补为匹配结果的事实。
- 没拿到有效结果时，Token 保留 `NULL`，通过 `turns_without_token_usage` 显示未知。
  报告 Token 合计只是**已知部分**，不能据此宣称总费用为零或总成本已确认。
- 取消不额外等待一次模型结果来估算费用，也不从自然语言/流式文字猜测用量。
- 崩溃或结束时写入失败的记录仍占用一次回合；耗时可能仅有预留时的零值，
  这是未完成测量的下界，不是已证明零耗时。没有结果即不能补算 Token 总成本。
- 继续请求重放不派发，不新增账本记录；不重置历史预算或返工轮数。

## 尚未完成的恢复边界

失败、取消或重启后不确定的 Claim 仍保留占用，不做超时释放/自动重试。
Task 仍为 `needs_human`。待开发：人工明确处置不确定 Claim、与服务管理的
运行中取消对接，以及受控状态回归。不能仅凭 Human 勾选“进程已停止”就宣称
外部 CLI 确定停止，更不能隐式重跑原意图。

后续第 4 子步骤 B 已提供[人工隔离处置](continuation-quarantine.md)；这是保留占用的
提交围栏，不是预算重置、进程停止证明或解除占用/重试授权。

账本回调不等于全局并发额度原子预约，尚不支持多 worker 总预算严格并发控制；
直接调用 TurnRunner 且不提供回调也不会自动记账。CLI exactly-once、真实供应商
费用和不可回滚文件副作用不在本次验收范围。

## 验证

`tests/test_failed_attempt_budget.py` 使用真实 SQLite 与离线 Fake Agent，覆盖启动/退出/
超时/解析/审计失败、启动中与会话中取消、预留及结束记账写入失败、错误 session
结果、额度耗尽、回执重放、账本持久化及身份/Token 冲突。完成守卫不放宽。
