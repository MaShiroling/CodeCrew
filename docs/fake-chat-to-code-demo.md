# P3.4 一键 Fake 聊天到编码演示

在项目根目录安装依赖后运行：

```bash
.venv/bin/python -m app.cli demo-serve --port 8000
```

不需要 Codex/Kimi/Claude CLI 或模型密钥。服务仅监听 `127.0.0.1`；终端会打印本次
临时示例 Git 仓库的绝对路径。若 8000 端口被占用，改用 `--port 8768`，浏览器地址
也相应改为 `http://127.0.0.1:8768/ui/chat/`。

1. 打开 `/ui/chat/`，新建房间“演示小修复”。发送
   `@白金 请讨论只修改 src/app.py，把 value 从 1 改为 2`。白金→月见→鲸鲸会用固定
   Fake 回复接话。此时 `/api/v1/tasks` 仍为空，示例仓库的 `value` 仍是 `1`。
2. 在刚发出的 **Human 消息**旁点击“以此发起受控编码任务”。仓库路径已预填本次
   临时示例仓库，允许写入范围显示为 `src`。目标填写“只修改 src/app.py，把
   value 从 1 改为 2”。点击“先预检，不授权”，核对完整 Git SHA、路径、目标和
   范围；预检不会改代码或建 Task。
3. 勾选单次授权确认框，点击“确认授权并创建任务”。跳到 `/ui/?task=...`，等待
   任务状态到“已完成”，查看 Diff、验证报告、Review 与下载 Patch。原始示例仓库
   保持 `value = 1`；修改只存在于隔离 Worktree 和交付 Patch。
4. 停止服务后本次临时仓库、数据库、Worktree 与证据均被删除。需要保留演示证据
   时，在停止服务前下载 Patch 或截图。

演示范围是**固定剧本**：Fake Implementer 无论自然语言如何描述，都只把该示例
`src/app.py` 从 `value = 1` 改为 `value = 2`。Planner/Reviewer 也是固定响应；
Verifier 的静态、公开与“隐藏”分类检查是真实确定性命令，但此演示的隐藏断言
并不对本机用户或代码仓库保密，不能称为抗作弊隐藏测试。服务端将聊天室预检与
授权限定到生成的示例仓库，并禁用直接 `POST /api/v1/tasks` 建任务；
`chat-demo` 和 `chat-serve` 的原有边界不变。仍然没有公网身份认证，不要对外开放。

自动验收：`.venv/bin/pytest -q tests/test_demo.py`。这验证同一应用内 Fake 聊天、
预检不执行、错误仓库拒绝、显式授权后完成守卫通过与 Patch 下载。2026-10-02
本机浏览器也实走了房间→三位 Fake 接话→预检→确认授权→工作台完成与交付证据。
真实三模型编码演示属于下一步 P3.5，不由 Fake 验收代替。
