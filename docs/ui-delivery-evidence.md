# 本地 UI 交付证据面板（7.4）

任务右侧的“交付证据”面板以持久化 Trace 和 Artifact 为依据，显示最近一次可恢复的确定性验证、
独立评审和 CompletionGuard 结论。面板不会把 Agent 的自然语言“已完成”作为成功证据。

## 读取与下载

- `GET /api/v1/tasks/{task_id}/delivery` 返回任务状态与修订号、验证检查及变更文件、
  评审结论/问题、守卫条件、最近验证绑定的 Diff Artifact，以及 `delivery_ready`。
  只有任务状态为 `completed`、验证与守卫通过、评审晚于最新验证，且存在绑定的 Patch，
  才显示交付就绪。没有证据时各段为 `null`；不能从空值推断检查通过。
- `GET /api/v1/tasks/{task_id}/delivery/patch/{artifact_id}` 只下载该任务**最近验证绑定**
  的 Git Patch；其他任务或同任务无关/旧的 Diff 均返回 404。下载前重新读取可信证据并校验
  Patch 的 SHA-256；完整性失败返回 500，不将损坏文件当作交付成果。
- 面板可预览相关 Artifact。未通过守卫或任务未完成时，Patch 按钮明确标为“最近验证 Patch
  （非最终）”；下载也不意味着任务成功。验证摘要仅给隐藏测试类别与结果，不返回其细节；
  既有原始 Artifact 预览接口仍可能展示更多内容，隐藏测试对 Agent 的隔离属于后续第 11 步。

面板与任务详情修订号不一致或证据读取失败时不展示旧结论，提供手动刷新。SSE/任务状态更新
会重新读取。该接口未提供身份认证，只能在可信本机使用；不应对公网开放。

## 验收边界

`tests/test_task_delivery_api.py` 检查空证据、完整成功链路、Patch 哈希与下载头、跨任务/
同任务无关 Diff 拒绝，以及篡改后的失败关闭。`tests/ui_control.test.cjs` 覆盖无证据、
加载失败、修订不一致和交付就绪的呈现。阶段 7.4 未运行真实模型浏览器端到端或完整视觉验收；
这些属于后续 7.5/第 8 步。
