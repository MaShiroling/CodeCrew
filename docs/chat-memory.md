# 聊天室长期记忆（Agent 自动提炼）

当前实现、评测结论与剩余边界统一见[记忆模块 v1 交付说明](memory-v1-delivery.md)；本页保留接口、配置和实现细节。

本实现参考[猫猫咖啡馆的记忆实现](https://github.com/MaShiroling/clowder-ai/blob/main/docs/features/F102-memory-adapter-refactor.md)的消息证据、短期上下文与长期记忆分层，但按 CodeCrew 的本地房间、只读 Agent 回合与权限边界落地；不是完整复刻。向量检索是可选的云端 embedding 扩展，默认关闭。

## 写入与召回

1. 原始房间消息持久化在 SQLite。当前讨论只附带同一 `correlation_id` 的有限历史；新讨论不自动回放旧消息。
2. Agent 在正常回复的结构化 JSON 中可附一条 `memory_proposal`（`decision`、`correction`、`preference` 或 `open_loop`），也可返回 `null`。这由模型判断值得记什么，不再由关键词规则自动创建待审核项，也不额外发起一次模型调用。提议的 `content` 必须是当前 Human 消息中不超过 200 字、足以表达该事实的连续原文分句；不再允许自由改写或添加建议。只有 Agent 成功回复后才尝试写入。
3. 服务端校验提议所指来源必须是**当前房间的本地 Human 消息**，且内容确实出现在该消息中；还会保守检查片段起点及紧随其后的否定/条件，防止把“不喜欢香菜”截成“喜欢香菜”。拒绝飞书发起的讨论和明显包含密钥、密码等敏感词的原文或提议。偏好/纠正提议另有归属守卫：第三方偏好和单纯“这不是我的偏好”的澄清不自动写入；混合表述必须有明确的本人偏好且提议与其有可核对的词项重合。这些都是防误写的启发式规则，**不能证明完整语义忠实**，可能漏写真实偏好。每条来源消息至多自动保存一条；重复处理幂等。写入时将来源、类型、`origin=agent_auto` 和状态一起持久化，**无需人工审核**。提议无效或写入失败不影响聊天回复。
4. 纠正可指定当前房间 active 旧记忆的 `replaces_memory_id`，原子地退休旧版并保留沿革；没有合法旧 ID 时不会擅自替换。用户仍可从自己的消息手动保存、查看来源和撤销。撤销后不再召回，也不会因重复处理而复活。
5. 默认用 ASCII 词和中文双字片段做确定性匹配；开启向量模式后，词项和向量分别取候选，再用倒数排名融合（RRF）排序，语义独有的候选也能进入结果。每次只从同房间 active 记忆中最多召回 3 条；同一讨论刚提炼的记忆不会再次注入，避免自我强化。每房间最多 200 条 active 记忆。记忆只是资料，不授予 Agent 新权限。

归属检查会识别“在家人共享房间里，”“在同事共用的聊天房间内，”等明确的位置短语；这表示 Human 对当前房间的要求，不因房间名称出现家人或同事就归为第三方偏好。位置短语仅在归属检查中跳过，落库原文仍保留完整范围。后续分句若是“家人喜欢……”或“他们喜欢……”仍会被第三方守卫拦截，其他房间仍不能召回这条偏好。该识别依赖有限句式，不能保证覆盖任意房间描述。

自动 `preference` 还有持续意图守卫：提议须带明确本人喜好/习惯、“以后/默认”等持续要求，
或明确房间内要求。仅说本轮怎样回答、一次性清单格式、疑问或未决定的偏好候选会保守拒绝；
检查提议周边原句，防止截掉“这次”或问号后冒充稳定表态。独立句子的明确长期偏好不会
仅因同条消息另有问题而被拒绝。本轮回答要求“没有记录就说明未知”不是长期偏好，
而“以后没有记录就说明未知”可作为明确持续要求。这是有限词面证据，可能漏写自然表述，
不是通用意图解析；只作用于未来自动提案，不追溯删除旧记录或限制 Human 手动保存。

## 派生全文索引与可选 BM25

[FTS5 索引维护](memory-fts-index.md)已接入应用启动与规范写事务：迁移 26、条件
创建 external-content 索引、活跃记忆回填，以及写入/替换/撤销/待办关闭同步。
使用[版本化确定性预分词](memory-fts-text.md)，原文不变；失败标记 `dirty` 或
`unavailable`，启动可审计重建。它不调用云模型；模块缺失仍可运行旧路径。
第 4 步已接入[可选 BM25 召回](memory-bm25-recall.md)。默认仍按上述旧词项与
可选向量/RRF 召回；配置 `CODECREW_MEMORY_LEXICAL_BACKEND=bm25` 后重启服务可
选择新关键词分支，改回 `legacy` 恢复旧分支。两者共用 RRF 常数 60 和范围守卫。
BM25 检索失败退回旧词项，向量失败保留当前关键词分支；返回前重新检查规范状态。
本轮开发验证只用临时数据库，未改私有配置或操作真实用户库，未测新路径 A/B 收益。

## 待办闭环

“工具尚未选定”“选型待定”只是未决状态，不能仅依据 Agent 后续建议自动成为 `open_loop`。对这类提议，服务端要求**提议的原文片段本身**包含明确的比较、评估、检查等行动要求；“还没决定，先比较两种方案”仍可自动写入，单独摘取“还没决定”则拒绝。否定行动和疑问句不会满足该行动检查。这是针对未决选型的保守补充守卫，其他任务措辞仍由 Agent 判断，不能视为完整的任务语义解析。

`open_loop` 记忆有 `open`、`completed`、`cancelled` 三种生命周期状态。Human 可在记忆列表中手动点击“标记完成”或“取消待办”；两者都是明确操作，不靠时间推断。Agent 也可在成功回复中给出 `memory_action`，但必须指向当前房间活跃的待办 ID，并附当前本地 Human 消息中的完整原文分句。服务端核查来源、明确的完成/取消措辞及与待办的唯一词项匹配；疑问、条件、否定或多条相似待办无法区分时不自动关闭。该启发式校验偏保守，不能代替语义判断；漏判时可手动关闭。

关闭操作保留待办原文、来源、关闭时间，以及自动关闭时的 Human 消息 ID；同一动作重复提交幂等，相反动作冲突。已关闭待办不再进入词项或向量召回，并删除其派生向量索引；历史仍可查看。没有自动到期或自动重开。

当本地 Human 明确询问某项待办是否仍在、是否完成/取消或其状态时，服务端只读同房间最近 50 条已关闭记录，并与活跃待办一起做保守词项匹配。只有唯一匹配已关闭待办时，才依据 SQLite 直接返回“记录中已完成/已取消”，**不调用 Agent 或云 embedding**，不把它重新注入普通长期记忆，也不声称能独立证明现实中的执行结果。活跃与已关闭记录同样相似、无法区分时也由服务端直接请 Human 在记忆列表中指定；无匹配时不会凭关闭记录作答。服务端直接答复的状态询问不会生成新的记忆或关闭动作。

已关闭状态路径覆盖“还在未完成/未关闭待办（清单/列表）里吗”等问法；“待办/状态/预约”
等通用词不计为识别具体目标的证据，仍要求至少两个非通用重合词项及唯一目标。
操作方法、是否要取消、假设完成/取消等请求不走关闭回执。相关 V3 评测核对实际取消
记录、精确服务端回执和未启动 Agent，而非仅检查回复包含“取消”；
见[真实失败与离线修复记录](../evals/baselines/memory-persistent-guard-regression-v3-2026-10-12.md)。

当 Agent 提交 `memory_action` 时，聊天室先核对并写入关闭结果，再由服务端生成用户可见的确认文字；不直接展示 Agent 对“已关闭”的自由表述。校验失败时会明确告知待办未修改。这个确认仅涉及记忆待办，不宣称关闭提醒或其他外部事项。未提交 `memory_action` 的普通讨论仍显示 Agent 原回复。

普通进度回复的提示词还要求保留 Human 表述的完成度：“还没完成”不等于“还没开始”。若需要 Human 进一步确认，必须请其同时说明具体待办和完成/取消动作；仅说“完成了”无法可靠匹配待办。此类自由回复目前依赖 Agent 遵循提示，仍需真实模型逐例审阅。

对唯一匹配的活跃待办，Human 询问状态、说明未完成或提出“如果完成”等条件时，服务端现在直接生成“仍开启、未修改”的回复，并给出包含待办原文与动作的确认示例；Agent 的自由表述不会覆盖这类状态回复。示例若过长、含敏感词或不满足现有关闭守卫，就只提示在记忆列表手动操作，不保证所有自然语言都能自动匹配。找不到唯一相关待办的其他聊天仍交给 Agent 回复。

## 可选的云端向量检索

兼容提供 `POST /embeddings`、`model`、`input` 和浮点向量响应的 HTTPS API。先在私有运行环境配置，**不要把真实密钥提交到仓库**：

```dotenv
CODECREW_MEMORY_EMBEDDING_MODE=on
CODECREW_MEMORY_EMBEDDING_BASE_URL=https://provider.example/v1
CODECREW_MEMORY_EMBEDDING_MODEL=your-embedding-model
CODECREW_MEMORY_EMBEDDING_REVISION=your-pinned-revision
CODECREW_MEMORY_EMBEDDING_API_KEY=your-private-key
# 可选：CODECREW_MEMORY_EMBEDDING_TIMEOUT_SECONDS=5
# 可选：CODECREW_MEMORY_EMBEDDING_MIN_SIMILARITY=0.65
```

`BASE_URL` 是 API 根路径，不含 `/embeddings`。未配置时默认 `off`，不发送数据、不调用云 API；设为 `on` 但缺少 URL、模型、版本或密钥时启动报配置错误。开启后，记忆文本在写入/补建索引时、检索问题在召回时会发给该服务商；请先确认其数据处理条款。敏感词命中的记忆或问题不会送往 embedding API，但这只是启发式过滤，不能保证识别所有秘密或个人信息。云调用失败、超时或向量维度不符时，检索退回本地词项路径，不妨碍消息与记忆落库。

向量是可重建的派生数据，原始记忆仍是唯一来源。默认 SQLite 路径在检索时按需补建已存在的 active 记忆，每次最多 10 条，以兼容部分服务商的批量上限；同房间最多 200 条，所以采用精确余弦扫描，不依赖 SQLite 向量扩展。模型地址、名称和手动固定的 `REVISION` 组成索引身份；换模型/版本后会逐步重建，维度异常不会混用。`0.65` 相似度门槛目前只是默认值，需用固定用例评测调校，不能视为已验证的最佳参数。

2026-10-12 增加[可选 Qdrant 混合召回](memory-qdrant-recall.md)：显式 `MEMORY_VECTOR_STORE=qdrant` 且 embedding on 才读已准备的版本化集合；缓存写入走 outbox，目标初始化/订阅/历史回填/投递仍需显式操作。该路径查询时**不补算历史向量**，只用匹配缓存及当前版本/hash，远端调用后复验规范状态/来源。未准备目标或发生故障时保留所选关键词；默认仍原 SQLite，不自动部署、同步或切换。具体限制、操作与无付费合成探针见该文档。

自动提炼可能误判或漏记；敏感词过滤只是防线之一，不是完整 DLP。当前服务没有公网用户认证，建议仅在可信本机使用，勿暴露到不可信网络。

原文片段校验只影响**未来的自动写入**：手动保存仍可由 Human 自行改写；已有自动记忆不会追溯重写。服务端还保守拒绝把“还没决定”标成已做决定，以及截掉“仅限/只在”等紧邻限制条件的片段。模型仍可能选错片段、分类错误，或将过期的相对待办持续保留，需通过来源查看和撤销处理。来源忠实性审阅与新约束的 Kimi 回归见[评测记录](../evals/baselines/kimi-extractive-memory-pilot-2026-10-09.md)。

归属守卫只作用于**未来的自动写入**，不会追溯删除已保存记忆，也不阻止 Human 经手动接口明确保存资料。已有误写仍需在记忆列表中手动撤销；“撤销旧偏好但不另存负面记忆”的自动操作尚未实现。

## 接口与兼容

- `GET /api/v1/chats/{room_id}/memories`：列出 active 记忆，含 `origin`、`kind` 和来源消息 ID。
- `GET /api/v1/chats/{room_id}/memories?include_closed=true`：额外列出最近 50 条已完成或已取消的待办。
- `POST /api/v1/chats/{room_id}/memories`：可选的手动保存，支持 `replaces_memory_id`。
- `POST /api/v1/chats/{room_id}/memories/{memory_id}/complete`、`/cancel`：手动完成或取消活跃待办。
- `DELETE /api/v1/chats/{room_id}/memories/{memory_id}`：撤销；原始消息与记忆沿革保留。
- `GET /api/v1/chats/{room_id}/memories/{memory_id}/history`：查看版本沿革。
- 旧版 `memory-candidates` 查询、审核与拒绝接口暂时保留，供历史待审核数据处理；新消息不再产生这类候选，网页默认不展示审核流程。

验证：使用假 Agent 返回 `memory_proposal`，然后开启另一话题并检查 `chat_context()` 的 `room_memories`；换房间、撤销、飞书讨论和无关话题应不召回。离线测试覆盖单轮与有界讨论、幂等、纠正沿革、来源边界和语义独有候选。[Kimi 的 20 条真实模型 pilot 基线](../evals/baselines/kimi-memory-v1-2026-10-08.md)已完成；[归属守卫后的重跑](../evals/baselines/kimi-attribution-guard-2026-10-08.md)写入 TP 16 / FP 0 / FN 0，检索 TP 10 / FN 1。[百炼云 embedding 的 20 条真实混合检索 pilot](../evals/baselines/kimi-hybrid-memory-pilot-2026-10-09.md)在临时阈值 0.50 下写入 TP 16 / FP 0 / FN 0，检索 TP 11 / FP 0 / FN 0；[原文片段约束后的回归](../evals/baselines/kimi-extractive-memory-pilot-2026-10-09.md)见单独报告。这些 pilot 验证了端到端可用性，但不是严格 A/B；回答语义与长期记忆效果仍待独立评估。

另有独立的 [16 条内容忠实性难例](../evals/memory-fidelity-v1.json)，覆盖未决事项被误标决定、否定/范围条件被截断、第三方偏好、相对时间被换算及模型添写建议。运行 `.venv/bin/python evals/check_memory_fidelity.py` 可在临时 SQLite 房间中走真实自动写入边界；不调用 Agent 或云 embedding，不更改冻结的 20 条基线。它只验证这些已标注提议的接受/拒绝，**不能证明真实 Agent 会选对片段，也不能替代语义审阅**。

真实 Kimi 单回合重放命令与结果复核要求见[记忆评测说明](../evals/MEMORY_BASELINE.md)。该运行器先在独立临时房间执行每条合成消息，提取实际记忆；是否符合原消息仍需逐例复核，不能仅凭来源级计数断言内容正确。

普通回复也必须遵守归属边界：“这不是我的偏好”不能改写为“我不喜欢”。本人选择未知时，替其点餐或配置方案前应先询问，不能以“稳妥/中性”为由预设不加、不用或另放。这些约束已加入聊天室 Agent 提示词；对应 4 条回答质量难例、v2 用户裁决与真实 Kimi 重放命令见[评测说明](../evals/MEMORY_BASELINE.md)。它独立于长期记忆写入守卫，结果需人工/Agent 语义审阅。

24 条挑战集真实回放发现一条房间内格式偏好漏写，以及已确认决定被重新说成待确认、明确禁令被弱化为建议。提示词现明确要求 Agent 提议保存持续适用的本房间格式偏好，即使当前没有待处理材料；回答时保留已记录决定和否定/条件的原有力度，不将“记忆可能过时”当作撤销证据，也不把其他房间的偏好设为当前房间默认值。三题真实 Kimi 回归已消除本次漏写和已决事项的表述问题；SQL 单题再次回归后能明确回答“生产环境不能开启”，但仍附带一个需新决策的采样设想，不宜把同题重复运行当作泛化验证。服务端写入守卫与检索阈值未改；详情见[全量基线与回归说明](../evals/MEMORY_UNSEEN_V1.md)。

## 当前版本验收边界

Kimi 的两条真实 `open_loop` 旅程分别覆盖自动写入、跨话题召回、完成/取消和 SQLite 重启后不再作为活跃记忆召回，证据与代码指纹见[旅程验收报告](../evals/baselines/kimi-open-loop-journey-2026-10-10.md)。随后新增的已关闭状态问答由 SQLite 直接返回，不耗模型额度；其重启、歧义和隔离行为已通过本地自动化测试。另已完成[Fake 浏览器主旅程](memory-browser-acceptance.md)，包括同库重启后的状态回执与来源查看；它不调用真实模型或云 embedding。这几个证据层次不能互相替代。

本地无付费复验可运行 `.venv/bin/python -m pytest -q tests/test_chat_memory.py tests/test_memory_open_loop_journey.py tests/test_standalone_chat_dispatch.py`；数据集和更广的回归命令见[评测说明](../evals/MEMORY_BASELINE.md)。真实 Kimi 或云 embedding 需要显式 `--live`/`--embed`，不属于默认测试。记忆模块可在可信本机作为当前版本使用；[24 条配对 A/B](../evals/baselines/memory-retrieval-ab-v1-2026-10-10.md)支持这一小样本中的检索收益，但不能宣称线上准确率、普遍收益、主动提醒或自动语义纠错。
