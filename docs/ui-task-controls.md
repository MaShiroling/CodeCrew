# 本地 UI 任务操作契约与验收（第 1 步）

本页确定交互与边界。创建表单、取消按钮及页面/API 联调均已完成。
后端已有 `POST /api/v1/tasks` 和 `POST /api/v1/tasks/{task_id}/cancel`。操作均在现有
静态 HTML/CSS/JavaScript 页面中接入，不增加前端框架或新的 Agent 路由。

## 创建任务

- 在任务工作台标题区放置“新建任务”入口，展开同页表单；字段只有 `repository_path`
  （目标 Git 仓库路径）和 `issue`（需求，支持多行）。不在页面输入或保存密钥。
- 前端检查两项内容去除首尾空白后非空，并遵守 API 的最大长度：路径 4096 字符、需求
  16000 字符。服务端仍是最终校验方；无效仓库由服务端返回 `422 invalid_repository`。
- 点击提交后禁用重复提交并显示进行中状态。请求为 JSON：

  ```http
  POST /api/v1/tasks
  Content-Type: application/json

  {"repository_path":"/absolute/path/to/repo","issue":"修复……"}
  ```

- 收到 `201 TaskView` 后才清空表单；使用响应中的 `task_id` 直接选中任务、加载详情并建立
  现有 SSE 连接。任务可能在页面切换前已结束，仍按返回状态展示，不把创建成功等同于任务成功。
- 服务端列表已改为最新任务优先，并有排序/分页回归测试，保证新建任务在第一页可见；
  页面仍直接使用创建响应中的任务 ID 打开详情，不依赖列表刷新结果。
- API 尚无创建幂等键。网络中断或响应丢失时不得自动重发 `POST`；保留表单内容，提示
  “任务可能已创建，请先刷新列表确认”，避免重复创建 Worktree。按钮只在本次请求待处理
  期间禁用，不能声称已解决跨请求的重复提交。

## 取消任务

- 只在选中非终态任务的详情区提供“取消任务”，要求用户确认；终态任务不显示操作。
- 使用当前 `TaskView.revision`，发送 `{ "expected_revision": N }` 到
  `POST /api/v1/tasks/{task_id}/cancel`。不允许用旧 revision 静默重试。
- 收到 `200 TaskView` 后刷新选中任务和列表；若状态为 `cancelled`，关闭 SSE 并显示最终记录。
  只有服务端确认后才显示“已取消”，按钮等待时禁用。
- `409 task_state_conflict` 表示状态或 revision 已改变：重新读取任务并提示用户确认最新状态，
  不自动再次取消。`404 task_not_found` 则清除失效选择并提示刷新。

## 错误与运行边界

| 情况 | 页面行为 |
| --- | --- |
| `422 validation_error` / `invalid_repository` | 在表单附近显示可理解的错误，保留输入；不创建成功状态 |
| `503 task_service_unavailable` | 说明服务未装配运行时；指向 `codecrew serve --config ...` 的本地启动方式 |
| `409 task_state_conflict` | 取消时重新读取当前任务，不自动重试写请求 |
| 网络失败、非 JSON 响应或 `5xx` | 保留输入/当前任务，显示失败或结果不明；不推断后台状态 |

服务必须通过 `codecrew serve --config <JSON>` 显式装配团队、验证命令和权限策略，
当前 CLI 仅绑定 `127.0.0.1`、单 worker。页面不提供逐任务模型选择；所用 Agent 由
服务端配置决定。默认 `app.main:app` 的任务 API 返回 `503`，页面需清楚呈现该状态。
当前没有用户认证、远程访问控制或不可信仓库隔离，**只能在可信本机使用，不应公网暴露**。
从 UI 创建任务不会改变 Verifier、Reviewer 或 CompletionGuard 的成功判定权。

## 实现与验收

1. 子步骤 2（已实现）：表单、创建请求、最新任务优先列表、创建后选中/SSE；覆盖非空校验、`201`、
   `422`、`503`、网络结果不明和重复点击。

3. 子步骤 4（已完成）：同进程页面/API 创建→查询→取消回归测试、离线测试、Ruff、使用文档和
   真实浏览器手工检查。浏览器中分别检查了默认未配置运行时的 `503` 提示，以及临时受控
   工作流里的创建、任务详情、团队对话、取消确认和终态更新。

可复现的无模型浏览器冒烟：

```bash
.venv/bin/python tests/manual_ui_smoke.py
```

脚本打印临时 Git 仓库路径，并在 `http://127.0.0.1:8765/ui/` 启动仅监听本机的服务。
在页面输入该路径与任意非空需求，创建任务后立即取消；按 `Ctrl+C` 退出时临时仓库会清理。
此脚本复用测试中的受控事件循环，不启动真实 Agent、不验证三模型协作或完成守卫结果。
真实模型 UI 端到端演示仍待后续验收。
