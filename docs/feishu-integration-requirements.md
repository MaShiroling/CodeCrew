# 飞书接入需求（v1 冻结）

状态：**D3～D6 已按本次开发请求冻结，功能已实现**。离线验收和平台限制见[验收记录](feishu-acceptance.md)；真实飞书长连接烟雾测试尚未执行。

## 1. 目标与定位

让用户在飞书里与 CodeCrew 的白金（Planner）、月见（Implementer）、鲸鲸（Reviewer）讨论话题，并看到三位 Agent 在有界对话中的接话。飞书是**独立聊天室的另一个入口**，不是新的编码授权入口。用户可以在飞书聊任何话题；要实际改代码，仍须回到 CodeCrew 已有的受控授权流程。

首版仅服务个人/小团队在本地 Mac 上运行的 CodeCrew。参考 [Clowder AI 的多平台聊天网关设计](https://github.com/MaShiroling/clowder-ai/blob/main/docs/features/F088-multi-platform-chat-gateway.md)与[飞书群聊设计](https://github.com/MaShiroling/clowder-ai/blob/main/docs/features/F134-feishu-group-chat.md)的分层思路：平台收发、外部会话绑定、内部调度、出站投递分离。CodeCrew **独立实现**，不复制其代码、文案、界面或品牌资产，也不引入其多平台/多账号体系。

## 2. 已冻结的决策

| 编号 | 问题 | 当前结论 |
| --- | --- | --- |
| D1 | 部署与收消息 | **已确认**：本地 Mac；首版优先飞书长连接，无需公网 Webhook。 |
| D2 | 群聊额度边界 | **已确认**：仅指定群和指定成员可以触发模型；不在白名单者不能消耗回合。 |
| D3 | 会话范围 | **冻结**：私聊 + 白名单群内真实提及当前 bot open_id 的文本；纯文本 @、@all、其他 bot 均不算。 |
| D4 | 机器人形态 | **冻结**：一个应用机器人，分别标注白金／月见／鲸鲸和短讨论标识。 |
| D5 | 编码权限 | **冻结**：只读讨论；飞书 external_source Human 即使从本地网页选择，也不能成为编码授权来源。新建 local Human 保持原流程。 |
| D6 | 会话映射 | **冻结**：每个 `(app_id, chat_id)` 稳定绑定一个房间；不自动新建/重绑，不提供 topic/thread 切换。 |

本次实现和验收均按以上决定执行。关闭房间或禁用绑定后不自动切换到另一个房间。

## 3. 用户故事

1. 我在与机器人私聊时发文本，或在被允许的群里 `@机器人` 发文本；消息进入对应 CodeCrew 聊天室，并保留“来自飞书的哪位用户”的可见归属。
2. 我可以在文本中指名 `@白金`、`@月见`、`@鲸鲸`；未指名时默认请白金先接话。Agent 在限定回合内可邀请队友继续，不要求我逐个点名。
3. 我能在飞书按发言顺序收到每位 Agent 的独立回复，并看出谁在说话、回应哪次讨论；不把三位回复拼成一段无身份文本。
4. 我在 CodeCrew 网页也能看到同一房间的原消息、发言者、Agent 回复和运行状态。飞书回复失败不抹掉内部对话记录。
5. 我看到明确的失败/额度耗尽/等待人工状态；机器人不能仅凭自然语言声称“代码已改好”。

## 4. 业务规则

### 4.1 入站

- 接收飞书应用机器人的文本消息事件。群聊仅处理**真实 @本机器人**的消息，不靠正文里出现机器人名称判断；`@所有人`不算。私聊按白名单策略处理。
- 仅允许配置的 `chat_id` 与 `open_id` 组合进入 Agent 调度。拒绝/忽略应可在本地诊断日志看到原因，但不暴露密钥或完整私聊正文。
- 同一飞书事件重投、同一 `message_id` 重复到达不得产生第二次 Agent 回合。机器人自己发出的消息不得回流触发。
- 仅文本为首版必需。图片、文件、富文本、表情、撤回、编辑先忽略并记录“不支持”原因，不提取附件或建立隐式文件权限。
- 解析飞书 `@机器人` 后仍须保留用户实际文本；Agent 指名需通过 CodeCrew 现有别名映射，未知 `@` 不得默默路由到某个 Agent。
- 同一群的不同人不能被展示成同一个“我”。至少保留外部发送者 ID 和安全的显示名/匿名短标识；不要求首版调用通讯录 API。

首版交互：私聊发送“讨论这个方案”默认由白金开场；群聊发送“`@CodeCrew 讨论这个方案`”也由白金开场；发送“`@CodeCrew @月见 请先分析`”则由月见开场。这里 `@CodeCrew` 必须是飞书对机器人的**真实提及**，`@月见` 是正文中的 CodeCrew 路由别名，不要求另建月见飞书机器人。

### 4.2 对话和预算

- 飞书消息进入 `StandaloneChatService`，复用现有只读 Agent 运行时和有界接话。外部平台不能直接驱动 Task、Worktree、Verifier 或编码授权端点。
- 一次用户消息只能启动一个有界对话 run；重复投递复用同一 run。复用已有有界 run 的 8 回合、600 秒硬上限及每次 Agent 超时；现有 bounded 路径没有独立总 Token 计数器，本次不宣称新增 Token 限额。
- 一个房间同时只允许一个活跃有界 run。新消息到来时不得混入进行中的上下文；首版明确返回“当前讨论进行中，请稍后再发”，不做隐式排队。
- 对话只使用当前房间、当前讨论链的有限上下文；不同飞书群/私聊之间不能串历史。
- 飞书消息中的“帮我改代码”“批准执行”等指令仍只是聊天文本，**不是授权**。

### 4.3 出站

- 每条已持久化的 Agent 回复按内部顺序投递到**同一个绑定的飞书会话**，使用“白金／月见／鲸鲸”标签；一个飞书机器人不伪装成三个独立飞书账号。
- 回复应标明对应的讨论或被回复消息；首版优先文本消息。使用官方回复 API 关联入站 `message_id`，同时保留短讨论标识；离线请求契约已验证，真实 API 尚待 live 验收。回复失败只重试，不降级到其他目的地。
- Agent 失败、讨论结束/预算停止要在飞书呈现简短状态；原始 CLI stderr、隐藏测试、密钥、本地绝对路径、工作区内容不得自动发出。
- 暂不做逐 Token 流式卡片、图片/文件、富文本、消息编辑与撤回同步。

## 5. 安全和运维要求

- 飞书 App Secret 和模型凭据只通过运行环境注入，不作为配置写入 Git、SQLite、API 或日志。App ID 是绑定与去重命名空间，必须保存在本机业务表，但不出现在状态端点或日志明文。外部用户自己发送的消息可能含敏感文本；本地消息保存原文，不声称自动净化数据库。缺少凭据/白名单时**启动失败或禁用连接**，不能退化为全员可用。
- 只连官方飞书端点；长连接断线要能观察到状态并自动重连。多进程服务器不得同时为同一机器人开启多个连接；首版限定单进程/单实例。
- 飞书正文视为不可信输入；不能提升 Agent 权限、访问别的聊天室、读取本地任意文件或触发代码执行。
- 记录 `trace_id`、平台事件 ID、内部消息 ID、run/turn ID、投递结果；日志默认脱敏，便于判定“飞书已收但 Agent 未回”“Agent 已回但飞书未送达”。
- 聊天消息和飞书身份属于可能包含个人信息的数据；首版仅在可信本机 SQLite 保存，文档需说明本地备份/删除边界，不公开部署。

## 6. 验收标准

1. Fake 飞书事件完成私聊和白名单群 `@机器人` 双向文本闭环，CodeCrew 房间与飞书出站可对应；非授权群/用户、无 @、机器人自发消息均不触发模型。
2. 白金 → 月见 → 鲸鲸的有界接话能按顺序显示为三条带身份的飞书消息；重复平台事件不会额外产生回合或回复。
3. 两个不同 `chat_id` 的房间、发送者和上下文完全隔离；同群两位允许用户在网页中可区分。
4. 断线、出站暂时失败、进程重启后有可检查的投递状态；重试不会重新调用模型。无法证明“绝对只送达一次”时明确采用“至少一次 + 去重/告警”语义。
5. 飞书端任何文本不能创建编码 Task 或 Worktree；缺密钥、缺白名单、越权成员均 fail closed。
6. 离线单元/集成测试先通过；真实飞书烟雾测试为显式开关，运行记录应含脱敏 trace 和具体结果，不把未跑过的线上能力写成完成。

## 7. 明确不做

首版不做多 IM 平台抽象、三飞书机器人、OAuth/用户登录、群管理命令、通讯录同步、文件/语音/图片、消息卡片与流式编辑、群内编码授权、公网 Webhook、多实例分布式调度。后续需求单独评审，不作为本次验收条件。
