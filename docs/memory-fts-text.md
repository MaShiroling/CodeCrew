# FTS5 中文与混合文本约定 v1

2026-10-11，完成检索升级第 **2/6** 子步骤。实现入口是 [`fts_text.py`](../app/chat/fts_text.py)，第 2 步完成时仅由离线测试调用；随后已用于[派生索引维护](memory-fts-index.md)和[可选 BM25 召回](memory-bm25-recall.md)，**默认仍未切换**。开发验证仅用临时库。第 1 步的题库、审核锁、旧检索输出和生产阈值均不变。

## 1. 选择与理由

采用**应用层确定性预分词 + FTS5 `ascii` tokenizer**：

1. 原始消息和规范记忆保持原文，不做归一化覆盖。
2. 只对派生文本执行 NFKC 和 casefold，处理全角/半角与英文大小写。
3. 中文连续汉字段生成重叠双字片段；ASCII 技术名和数字按下面规则生成词项。
4. 每个词项按“类型前缀 + UTF-8 十六进制”编码，词项间用空格隔开，交给 `ascii` tokenizer。
5. 查询走同一规则，编码后用引号包住各词项，程序生成 OR 候选查询；将整个 MATCH 表达式通过 SQL 参数绑定。

这是字符 n-gram 与规则切分，**不是基于词典的中文语义分词**，也没有同义词扩展、简繁转换、拼写纠错或词干化。不把“异步作业”和“后台任务”自动视为等价，语义改写仍由向量分支补充。

| 候选方案 | 取舍 |
| --- | --- |
| 直接使用默认 `unicode61` | 连续 token 字符形成一整个词项；不能依赖它从无空格中文长句中识别双字短词 |
| 直接使用 `trigram` | 全文查询不匹配不足三个字符的片段，不满足“超时”“上线”等两字查询 |
| 引入词典分词器 | 可以提供词级中文分词，但增加词典版本、专业词覆盖及运行依赖；当前不引入，后续如有收益可另做版本对照 |
| 本次确定性预分词 | 支持双字中文短词，可复验，不需要下载词典；代价是更长派生文本与部分片段误匹配，需后续 A/B 判断 |

前两项依据 [SQLite tokenizer 文档](https://www.sqlite.org/fts5.html#tokenizers)与[trigram 限制](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)。本机内存库验证：“网关读超时统一为8秒”用原始默认 tokenizer 或 trigram 查询“超时”均无结果，按本方案编码则命中。它只证明该例的匹配行为，不是检索质量或性能结论。

## 2. 词项规则

以下展示便于理解的**未编码词项**；实际派生字段是 ASCII 编码。

| 输入 | 词项示意 | 约定 |
| --- | --- | --- |
| `数据库` | `h:数据`、`h:据库` | 滑动双字片段；不补词典中的完整“数据库”词项 |
| `超时，上线` | `h:超时`、`h:上线` | 不跨标点、空格或中英边界造片段 |
| `API网关` | `w:api`、`h:网关` | 中英分别处理 |
| `ＲＡＢＢＩＴＭＱ` | `w:rabbitmq` | 仅派生字段全角归一化与大小写折叠 |
| `C++` / `C#` / `C` | `t:c++` / `t:c#` / `w:c` | 区分技术名，不都降成 C |
| `v1.2.3` | `t:v1.2.3` | 版本保留完整，不拆成 1、2、3 |
| `8.5` / `8` / `80` / `-8` | 各自独立 `n` 词项 | 不把小数、整数、符号或前导零统一成同一个数 |
| `8ms` | `t:8ms`、`n:8` | 受支持 ASCII 单位提供数字别名；不声称时间单位语义等价 |
| `memory_embedding_mode` | 完整 `t` 词项，加 `w:memory`、`w:embedding`、`w:mode` | 标识符既保留全名，也可按组件找候选 |
| `/api/v1` | 完整 `t` 词项，加 `w:api`、`w:v1` | 路径可按组件匹配；不是完整路径等价证明 |
| `.env` | `t:.env` | 点号技术词保持原子；裸 `env` 不自动与它等价 |
| `库` / `秒` / 表情 / 仅标点 | 无词项 | v1 不做中文单字召回，不把空查询变成全表检索 |

含点号、冒号、加号、井号或 @ 的复杂 ASCII 词保持完整，不做组件扩展；其余下划线、斜杠、连字符组件仅补含字母的部分，避免从版本/范围中随意拆出数字。当前规则只针对中文与 ASCII 技术文本，不保证其他语言自然词切分。汉字范围覆盖基本汉字、扩展 A 及补充平面范围，并有补充字符测试。

支持单位列表固定为 `ms / s / kb / mb / gb / tb / hz / khz / mhz / ghz`。未覆盖的单位、科学计数法或日期不能假装已经做了规范语义解析。数字与符号匹配约定不代替最终回答里的数量/单位核验。

## 3. BM25 与查询语义

[`tokenize_fts_text`](../app/chat/fts_text.py) 返回按出现顺序排列的 `FTSToken`。文档端**保留重复出现**，不能先转集合，否则会抹掉 BM25 的词频；查询端去重，避免同一个词反复构造 OR 分支。

`build_fts_query` 去掉查询开头的 `@收件人`，随后和文档使用同一预分词规则。文档端不删除来源中的 @ 文字，不改原文。“OR / NOT / NEAR”、双引号、星号、列名前缀等用户文字只能产生编码后的字面词项，不会直接成为 FTS 运算符。[官方查询语法](https://www.sqlite.org/fts5.html#full_text_query_syntax)说明 MATCH 自身有操作符，因此**只做 SQL 参数绑定还不等于把用户 FTS 表达式当作普通文字**。

选择 OR 是为了生成候选，再由 BM25 和后续 RRF 排序，不强制长自然语言问题中的每个词都匹配。但它不是完整短语匹配：查询“生产兜底”可能同时找到“生产禁止兜底”和“联调允许兜底”。技术词组件、通用中文片段和数字别名也可能带入干扰项。**命中不代表同一范围、条件、否定或事实已经得到证明**，原文与来源守卫和回答质量评测不能移除。

编码是可逆的文本表示，不是哈希、加密、脱敏或 SQL 参数绑定的替代品；不要把派生字段作为隐私保护承诺。片段增加和组件补充也改变 BM25 文档长度/词频分布，后续必须比较收益，不能从匹配测试直接推断召回率更高。

## 4. 边界与版本

- 文档输入最多 4096 字符；目前规范记忆本来更短。查询最多 1024 字符、64 个去重词项；归一化前后都检查字符限制。
- 超限抛 `FTSTextLimitError`，不默默截断意图。索引维护遇到超限会回滚派生变化并标记失效；第 4 步查询接入遇到超限会退旧关键词，不标记健康索引损坏。
- 空/不可检索查询返回 `None`；后续调用方应返回空关键词候选，不能执行 `MATCH ''` 或省掉 WHERE 后读全表。
- `FTS_TEXT_VERSION = codecrew-fts-text-v1` 固定规则；`FTS_TEXT_REVISION` 还包含 Python 使用的 Unicode 数据版本。本机为 `codecrew-fts-text-v1:unicode-14.0.0`。
- 后续索引元数据要记录该 revision，规则或 Unicode 版本变化须重建派生索引，不能继续用旧 token 文档对新 token 查询。这项持久化/重建尚待第 3 步实现。

本步新增的是不访问数据库的纯文本组件；内存 FTS 表只存在于测试，未增加数据库迁移、第三方依赖、业务配置或 production import。
