## 合成规模：1024-D，三个查询/档，每臂 60 样本

四档各自独立规范 SQLite 和 collection，经真实 outbox 投递；初始双向 audit 全量
10/10、50/50、200/200、1000/1000 一致，均无 pending/processing/waiting/dead。
规模数据用固定随机种子的正交干扰向量、明确目标和成功空结果；查询类别是词项
命中、语义路径、无结果。其他房间中也有与查询相同方向的点，不能混入本房间。
这是存储/编排负载，不将合成命中百分比当真实模型质量。

| 本房间候选 / 当前集合总点数 | BM25 p50 / p95 | SQLite hybrid p50 / p95 | Qdrant hybrid p50 / p95 |
| --- | ---: | ---: | ---: |
| 10 / 10 | 0.732 / 1.321 | 3.028 / 3.788 | 9.288 / 11.714 |
| 50 / 50 | 0.982 / 1.826 | 7.006 / 8.193 | 23.598 / 27.508 |
| 200 / 200 | 1.983 / 2.626 | 21.815 / 22.549 | 84.161 / 92.393 |
| 200 / 1000 | 2.129 / 3.825 | 22.157 / 23.815 | 85.563 / 97.416 |

所有档位两混合分支的有序来源和完整向量排序相同。总点数 1000 **不等于搜索 1000
候选**，本房间仍 200；其他 800 点仅为范围干扰。Qdrant `exact=true`，未做 HNSW
调参、并发/QPS、百万向量、统计显著性、冷热缓存隔离或生产负载测试。
SQLite 规范文件字节数依次 339,968 / 688,128 / 1,949,696 / 8,560,640，包含消息、
FTS、outbox 和向量，不等于向量库纯占用，也不是跨后端内存/存储成本比较。

## 决策与解释边界

**保留 `MEMORY_VECTOR_STORE=sqlite`，Qdrant 继续可选；关键词 default legacy 也不动。**
当前 <=200 候选下，Qdrant 接线没有新增质量收益，也没有展示应用检索速度优势。
不能为使用外部服务而切默认，更不能把本轮精确检索说成 ANN 加速。

从代码和请求计数看，Qdrant 路径包含多次远端元数据校验、规范/缓存快照逐候选校验、
完整版本过滤 JSON 与读后复验，这些都是额外开销的合理候选原因；**这是推断，未做
profile，不能归因于 Qdrant 引擎慢**。后续优化可以验证批量快照/元数据校验复用，
但必须保留版本栅栏、来源守卫和复验，再跑配对质量/故障矩阵；本轮不顺势改业务实现。

Qdrant 的已验证价值是明确的存储边界、派生索引、可靠投递/审计/恢复，以及可选服务
接线；不代表此规模比 SQLite 更合算。若将来扩大规范候选、改变检索契约或考虑 ANN，
另开阶段定义质量退化容忍度/权限/索引参数，再做独立盲测及并发负载。
