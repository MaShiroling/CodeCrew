# 云端 embedding 阈值留出集：单候选离线重放

在查看留出集向量之前，先根据[调试集报告](embedding-threshold-tuning-2026-10-09.md)锁定候选阈值 **0.50**，并写入 [`memory-threshold-candidate-v1.json`](../memory-threshold-candidate-v1.json)。该文件绑定数据集、无关记忆对照、embedding 模型指纹和调试集报告的 SHA-256。留出集脚本只接受锁定候选，不接受新的阈值列表。本次只调用百炼 `text-embedding-v4` 为 10 段尚未缓存的合成文本生成向量，没有重跑 Kimi，也没有按留出集结果调整阈值。

输入是 Kimi 关键词基线的 8 条冻结留出用例 `20261008T061157Z-6f2bffa6`，外加 4 条“同房间无关记忆”反事实对照。逐题机器报告保存在本机 Git 忽略目录 `evals/results/memory-threshold-v1/20261008T163820Z-85e8e5c6-holdout.json`。

原始留出用例的召回来源逐题不变，因此本次留出集只能说明候选阈值在这些用例上**没有退化**，不能证明它带来新收益。唯一误召回来自对照 `dev_type_hints__vs__dev_docs_open_loop`：关于 Python 公共函数类型标注的记忆提到了“静态检查”，而文档链接检查的问题也含“检查”。两者不相关，但关键词重叠使关键词检索召回记忆；该对的向量相似度为 **0.4471**，低于 0.50，混合检索没有增加误召回。这暴露的是现有关键词检索的宽松匹配问题，不应记作向量阈值引入的错误，也不应修改留出集负例来消去它。

结论：0.50 保留为**待验候选**，暂不改生产默认 0.65。后续已用相同阈值完成 [Kimi 真实混合检索 pilot](kimi-hybrid-memory-pilot-2026-10-09.md)；10 条反事实对照由用户委托 Agent [逐项审阅并接受为 pilot 负例](memory-controls-fidelity-audit-2026-10-09.md)，但这不是独立人类标注。原 20 条样本很小，且该留出集已被先前关键词基线观察过；这不是严格盲测或线上效果证明。
