# Kimi + 百炼混合记忆：20 条真实模型 pilot

在[调试集阈值扫描](embedding-threshold-tuning-2026-10-09.md)与[单候选留出集离线重放](embedding-threshold-holdout-2026-10-09.md)之后，本轮用已锁定的 **0.50** 阈值，运行 Kimi Code Agent 与百炼 `text-embedding-v4` 的真实聊天室链路：Agent 回复并自动提炼记忆、SQLite 持久化及向量索引、下一讨论的记忆召回。仅通过命令行环境变量临时覆盖阈值，`.env` 和生产默认 **0.65** 均未修改。用例全是合成数据。

第一次单条尝试在受限环境里 Kimi 进程以 exit 71 失败，未产生可评分的记忆结果；联网环境下同一用例随后完整成功。正式结果分别保存在本机 Git 忽略目录 `evals/results/memory-baseline-v1/20261008T165137Z-8cc03d7d/`（调试集 12 条）和 `evals/results/memory-baseline-v1/20261008T170108Z-4cfd8eb9/`（留出集 8 条）。两个 manifest 记录相同的数据集、模型指纹与 0.50 阈值，不包含密钥。

| 本轮分组 | 完成用例 | 写入来源 TP / FP / FN | 召回来源 TP / FP / FN |
| --- | ---: | ---: | ---: |
| 调试集 | 12/12 | 10 / 0 / 0 | 6 / 0 / 0 |
| 留出集 | 8/8 | 6 / 0 / 0 | 5 / 0 / 0 |
| 合计 | 20/20 | 16 / 0 / 0 | 11 / 0 / 0 |

本轮 `personal_chinese_preference` 中，Kimi 自动写入“默认使用中文回答”，随后问题正确召回该记忆。按当前关键词分词函数，问题与本轮新写入的记忆**没有共同词项**，因此这条是实际向量补召回，而非关键词命中。同一用例在独立的单条预演中也成功写入并召回。

旧关键词基线的相应两组汇总为写入 16 / 0 / 0、召回 10 / 0 / 1；本轮为召回 11 / 0 / 0。但两轮重新调用了非确定性 Kimi，记忆文本和回复可能变化，且运行时相关代码指纹不同，所以 **不能把 1 条差异直接归因于阈值或向量功能**。同输入的离线重放才隔离了检索阈值差异；真实运行则验证了端到端可用性。本 pilot 样本量小，留出集也非严格盲测，不代表线上效果。

失败回退方面，现有 [`test_vector_memory.py`](../../tests/test_vector_memory.py) 已用模拟 embedding 故障验证记忆不回滚、检索退回关键词；本轮云服务没有真实故障，不能据此声称线上故障恢复已实测。首次索引和 Agent 不同措辞在本轮真实路径中得到覆盖，但尚无延迟或成本统计。

来源级全对不等于内容完全忠实。[后续 Agent 逐项审阅](memory-controls-fidelity-audit-2026-10-09.md)接受 10 组反事实无关记忆对照，同时发现 3 处明确需要修正的内容偏离或时效风险，以及 7 条包含未获来源直接支持的附加说明；它不是独立人类标注。所有回答质量仍标记 `pending_human_review`。

当前结论：0.50 可继续作为候选，但**暂不推广为生产默认**。下一项开发优先处理自动提炼的来源忠实性，然后补齐同代码、同模型条件下的关键词/混合对照和独立新用例。
