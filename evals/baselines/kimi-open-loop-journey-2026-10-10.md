# CodeCrew 待办记忆旅程验收（2026-10-10）

本报告只冻结两条**分别运行**的 Kimi Code implementer 真实旅程，不把它们伪装成一次全量批次，也不把评测器的机器判定当作大样本成功率。原始逐例 JSON 与 manifest 保存在本机 Git 忽略的 `evals/results/memory-open-loop-journey-v1/`；报告不包含密钥。

两次 manifest 的数据集 SHA-256 都是 `77d0cdac04f67bbab533d662be7798e1bd649e1db079e563b7b1d918ef279ac8`，`app/chat/memory.py`、`app/chat/dispatch.py`、`app/chat/store.py` 和运行器指纹也分别一致。每次 `summary.json` 都是 1/1 回合链完整、1/1 写入、1/1 机器旅程匹配；合起来覆盖了完成和取消两类正例，但不是同一次运行的 2/2。评测不调用 embedding；最后一步只检查重启后**检索上下文**，没有向 Kimi 发送第三个问题。

逐例查看回复：两条关闭确认都与 SQLite 状态一致，不宣称已操作提醒。个人场景第一轮“出门前顺手提醒一声”的措辞可能让人误以为系统会主动提醒；当前项目没有主动提醒调度，不能把这句话视作已实现能力。机器结果中的 `semantic_review=pending_human_review` 保持原样；这里是 Agent 辅助审阅，不替代 Human 最终裁决。

在上述真实运行**之后**，`app/chat/dispatch.py` 增加了已关闭待办的只读状态问答：唯一匹配时由 SQLite 直接回复，歧义时要求指定，不调用 Kimi 或 embedding，也不把已关闭待办注入普通记忆。当前文件 SHA-256 已不同于两次 manifest，所以真实运行**不证明新增状态问答已经过在线验收**。该确定性路径由重启、完成/取消、歧义、房间和外部消息边界的本地测试验证；若需要 UI 实机证据，须另做本机手动演示。

本轮无付费调用的回归：12 个记忆/聊天室测试文件共 115 项通过，`node --test tests/ui_chat.test.cjs` 通过，`ruff check .` 通过。数据集默认校验：20 条基线、16 条忠实性离线守卫、4 条回答质量、6 条关闭难例和 2 条旅程全部通过。**这些数字是测试与样本计数，不是线上准确率。** 过去的 20 条混合检索 pilot 仍不能构成严格同代码 A/B，也不证明长期记忆在真实使用中的稳定性。

全库 `pytest -q` 本轮并非全绿：初次运行出现 17 failed、7 errors。包括一个记忆迁移版本断言仍写 24（当前迁移为 25），已修正并在上述相关回归中通过；其他问题位于 continuation 测试、三 Agent 预检桩重复传入 `env_source`，以及当前受限环境无法启动 macOS `sandbox-exec` 的边界测试。修正迁移断言后未重跑整库，因此不能声称全库仅剩某个精确失败数；这些问题不计入记忆模块通过项，也没有在本轮改动无关实现。

当前版本边界：自动提炼仍可能语义误选或漏记；已关闭状态问答仅覆盖同房间最近 50 条已关闭待办和可唯一词项匹配的明确询问，不证明现实任务确已完成；相似项要 Human 指定。撤销旧偏好但不另存负面偏好的自动操作、主动提醒、自动过期、生产级密钥/DLP 与大样本盲测均不在本轮交付范围。
