# Kimi 真实待办闭环 pilot：状态通过，回复一致性待复验

单例探测目录：`evals/results/memory-open-loop-v1/20261009T092914Z-8f604130/`。全量 6 条目录：`evals/results/memory-open-loop-v1/20261009T093126Z-1f5adfc9/`。两组均由用户在本机通过隐藏输入密钥运行；目录由 Git 忽略。每条使用临时 SQLite 房间，先预置来源合法的 `open_loop`，再由 Kimi Code implementer 在一个真实 Agent 回合中处理当前 Human 消息。不调用 embedding；结果目录包含当时的数据集和代码指纹，不包含密钥。

全量机器状态为 6/6 回合完成、6/6 目标待办状态匹配、4 条负例误关 0、额外活跃记忆 0。明确完成与取消均被接受；未完成、条件、疑问均未提议关闭；“两条相似待办”中 Agent 提议关闭其中一条，服务端因指向不唯一拒绝，两条保持 `open`。这验证了当前小样本上的服务端防误关效果，不代表线上误关率为零。

逐例审阅发现用户可见回复与持久化状态不完全一致：相似待办拒绝关闭后，Kimi 没有说明两条待办仍开启；取消成功后，Kimi 声称“相关的提醒也一并关掉”，但系统只关闭记忆待办，没有提醒操作。故此轮仅计为**状态闭环通过**，不计为回复语义全通过。

审阅后修改了聊天室单轮与有界讨论路径：收到 `memory_action` 时，服务端先执行守卫和持久化，再以实际结果生成确认或“未修改”回复，代替 Agent 的自由表述；提示词也禁止声称操作提醒。修改发生在上述运行**之后**，不能用旧结果证明新回复行为。离线假 Agent 回归已覆盖接受、拒绝和伪造提醒表述；还需在同一新代码下重跑上述 6 条真实 Kimi 用例，并检查逐例回复。

服务端确认逻辑修订后的第二轮全量结果位于 `evals/results/memory-open-loop-v1/20261009T094146Z-7ba07935/`。6/6 回合成功、6/6 状态匹配、误关 0；“两条相似待办”明确回复未修改，取消回复不再虚构提醒操作。但 Agent 自由回复仍有两处语义瑕疵：`dev_not_completed` 把“还没完成”推成“还没开始/一动没动”；`personal_question_complete` 建议 Human 只说“完成了”，而服务端要求关闭依据与具体待办有足够词项重合，该短句无法自动关闭。第二轮不能称为回复质量全通过。

因此又在单轮和有界讨论提示词中增加两条规则：未完成不等于未开始；请 Human 再确认时必须同时说出具体待办和完成/取消动作，不承诺单独回复“完成了”即可关闭。此修订发生在第二轮**之后**；已有结果保留，不追溯改分，仍需新代码下真实 Kimi 回归。

针对这两条问题的真实 Kimi 单例重放 `evals/results/memory-open-loop-v1/20261009T095040Z-92fcba16/` 中，`dev_not_completed` 与 `personal_question_complete` 状态均保持 `open`，回复分别保留“尚未做完”的原义、要求 Human 同时说出具体事项和动作。随后同版完整 6 条重跑位于 `evals/results/memory-open-loop-v1/20261009T095335Z-b5379354/`：仍为 6/6 状态匹配、误关 0。不过 Agent 在该轮的条件句和询问回复中再次建议只说“已取消”或“已完成”，这些短句与待办文本词项重合为 0，无法通过服务端关闭守卫。提示词约束没有稳定解决误导性建议，因此此轮也**不能**标为回复质量全通过。

完整重跑后，单轮和有界讨论路径对“未完成、条件、完成状态疑问”且唯一匹配活跃待办的消息改用服务端状态回复，不再显示 Agent 对这些场景的自由表述。服务端确认待办仍开启、未修改，并只给出经关闭守卫预检的完整示例；遇到多个相似待办、过长或不适合生成示例的内容，则引导在记忆列表中指定并手动操作。离线假 Agent 测试覆盖这三类状态、相似待办歧义和示例可执行性。该后端修订发生在上述第三轮**之后**，尚需新的真实 Kimi 回归。

针对上述三类风险的真实 Kimi 定向重放保存在 `evals/results/memory-open-loop-v1/20261009T154750Z-219d3cfd/`，与随后两条写入→关闭旅程使用相同的 `app/chat/dispatch.py` 指纹。3/3 回合完成、3/3 待办仍开启、误关 0，服务端回复分别保留“还没完成”的原义、指出条件句不能证明完成、指出问句不能证明现实进度；示例均包含具体待办和动作。此结果只覆盖这三条定向负例，**不是修订版完整 6 条重跑**。其后又新增了已关闭待办的只读状态问答，当前调度代码指纹再次变化；新功能的验收边界见[旅程报告](kimi-open-loop-journey-2026-10-10.md)。
